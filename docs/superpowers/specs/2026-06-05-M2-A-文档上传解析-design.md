# M2-A 文档上传/解析 Design

- 日期：2026-06-05
- 类型：子系统 spec（在总体架构 §2 + M0 数据模型范围内落地 M2-A）
- 状态：已评审通过

## 0. 范围

按 M2-PoC 结论（**主选 POI**），落地 M2-A：**文档上传/解析/统一富文本存储/下载**（编辑锁、版本链、diff 留到 M2-B）。

完成判据：
- 上传 docx → POI 转换 → knowledge + knowledge_version 双表落库 → 原文件存 MinIO
- GET 当前版本 HTML / GET 原文件，能正确跨租户 + 越权 403
- 全链路测试：unit + IT（真实 Postgres + 真实 MinIO + 真实 JPA 转换）

## 1. 已确认参数

| 维度 | 决策 |
|------|------|
| 文档/版本粒度 | 1 knowledge + N versions（按 M0 spec 完整数据模型，1 个 knowledge + 多条 version 行） |
| 存储表示 | HTML（POI 产出） + 原 docx（MinIO 引用） |
| 原文件存储 | M0 ObjectStorage 端口（MinIO 生产 / InMemory local-mock） |
| 鉴权 | M1 check(user, node, WRITE) 守住；读走 check(user, node, READ) |
| 文档格式 | M2-A 限 docx（PPTX/Excel/PDF 留 M2 后续子 PoC） |

## 2. 数据模型（V3 迁移）

### 新表

```sql
-- 一条"知识"= 一个逻辑文档
CREATE TABLE knowledge (
    id                 BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    tenant_id          VARCHAR(64)  NOT NULL,
    catalog_node_id    BIGINT       NOT NULL,    -- 知识所在目录节点
    title              VARCHAR(500) NOT NULL,
    doc_type           VARCHAR(20)  NOT NULL DEFAULT 'WORD',  -- WORD|MD|TXT|...; M2-A 仅 WORD
    status             VARCHAR(20)  NOT NULL DEFAULT 'PUBLISHED',  -- DRAFT|UNDER_REVIEW|PUBLISHED|ARCHIVED|DELETED
    current_version_id BIGINT,                              -- 当前发布版本（与 knowledge_version 互指，FK 后建）
    created_by         BIGINT       NOT NULL,
    created_at         TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at         TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_knowledge_tenant_node ON knowledge (tenant_id, catalog_node_id);
CREATE INDEX idx_knowledge_tenant_status ON knowledge (tenant_id, status);

-- 每次保存/审核通过 → 新版本
CREATE TABLE knowledge_version (
    id                BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    tenant_id         VARCHAR(64)  NOT NULL,
    knowledge_id      BIGINT       NOT NULL,
    version_no        INT          NOT NULL,    -- 1, 2, 3, ...
    content_richtext  TEXT         NOT NULL,    -- 统一富文本 (POI 出的 HTML)
    original_file_key VARCHAR(500),              -- OSS 引用
    file_format       VARCHAR(20),               -- "docx"
    change_type       VARCHAR(20)  NOT NULL,     -- CREATE|UPDATE|ROLLBACK
    parent_version_id BIGINT,                    -- 上一版本（M2-A 创版时为 NULL）
    editor_id         BIGINT       NOT NULL,
    created_at        TIMESTAMPTZ  NOT NULL DEFAULT now(),
    comment           TEXT,
    UNIQUE (knowledge_id, version_no)
);
CREATE INDEX idx_kv_tenant_knowledge ON knowledge_version (tenant_id, knowledge_id);

-- 把 knowledge.current_version_id 反向 FK 加上
ALTER TABLE knowledge ADD CONSTRAINT fk_knowledge_current_version
    FOREIGN KEY (current_version_id) REFERENCES knowledge_version(id) DEFERRABLE INITIALLY DEFERRED;
```

## 4. 上传流程

```
POST /api/knowledge
  Headers: X-Tenant-Id, X-User-Id
  Body (multipart/form-data):
    - file: <docx 二进制>
    - catalogNodeId: <Long>
    - title: <String 可选，默认从 HTML 抽首 H1>
  Auth: check(userId, catalogNodeId, WRITE)

  流程:
  1. 上传 docx 到 OSS:
     key = "tenant-{tid}/knowledge/{uuid}/v1/original.docx"
     objectStorage.put(key, in, size, "application/vnd.openxmlformats-officedocument.wordprocessingml.document")
  2. POI 转换（重新读 stream，避免 OSS 往返）:
     html = converter.convert(docxStream)
  3. 抽 title: 优先 request.title，否则 DefaultTitleExtractor.from(html)
  4. INSERT knowledge (status='PUBLISHED', current_version_id=NULL, created_by=userId)
     注: 先 insert knowledge 拿到 id，再 insert version，最后 UPDATE knowledge.current_version_id
     (用 @Transactional 保证; current_version_id FK 设为 DEFERRABLE 解决互指)
  5. INSERT knowledge_version (knowledge_id, version_no=1, change_type='CREATE', content_richtext=html,
     original_file_key=key, file_format='docx', parent_version_id=NULL, editor_id=userId)
  6. UPDATE knowledge SET current_version_id = ? WHERE id = ?
  7. 返回 KnowledgeView + version_no=1 + content_richtext
```

**关键决定**：不通过 knowledge_id 算 OSS key（POI 转换需要输入流，要么 OSS 往返要么保留原 stream）。当前方案：**先保留原始 stream 转 POI，再 put 到 OSS**——两次解析但避免依赖。

**简化（推荐）**：使用 `InputStreamSupplier` 或 `byte[]` 中转。M2-A 接受内存中转（docx 几十 MB 级不超 50MB）。**生产 M2-B+ 应改成分块流式**。

## 6. 端口切分

为让 `DocumentService` 单元可测 + 复用 M2-PoC 的 `Converter` 抽象：

```java
// com.kep.document.api.Converter
public interface Converter {
    /** 方案名 */
    String name();
    /** 输入 docx 流,输出 HTML 字符串 */
    String convert(InputStream docx) throws Exception;
}
```

`PoiDocxToHtml` 直接复用 M2-PoC 的实现，加 `@Component`。

> 为什么不把 M2-PoC 的 `poc-conversion/` 直接 import 到主项目？
> - M2-PoC 是独立子项目，自带 pom 与 Node/LO 依赖；引入主项目会污染 KEP 构建
> - 复制 80 行 POI 代码代价低
> - M2-PoC 的 demo 仍可作为未来 fallback（Mammoth）的试验场

## 9. 关键设计取舍

- **POI 直接接 M2-PoC 的 80 行实现**，不重写。代价：M2-A 继承 POI 的所有保真度局限（颜色/页眉/超链接丢）。M2-B+ 可增量补。
- **不走 OSS 往返**，POI 转换复用上传时的内存中转。生产 M2-B 应改流式（M2-A 接受内存中转的简化）。
- **current_version_id 与 version 行互指 FK DEFERRABLE**，避免"先插哪个"的死锁。
- **M2-A 不实现审核/编辑锁**，知识发布即 PUBLISHED；M4（审核）+ M2-B（编辑锁）会改 status / 加 edit_lock 表。
- **knowledge.title 默认从 HTML 首 H1 抽**，POI 抽 H1 可靠（M2-PoC 已实测）。
- **跨租户安全**：knowledge 继承 catalog_node 的 tenant 隔离 + M1 的 ACL 层。
- **M2-A 限 docx**：M2-PoC 只评了 docx，PPTX/Excel/PDF 留后续子 PoC（按同方法跑 1-2 天评估）。

## 10. 不在 M2-A 范围

- 编辑锁、版本回滚、diff（**M2-B**）
- 审核工作流（**M4**）
- PPTX/Excel/PDF 转换（**M2 后续子 PoC**）
- 在线富文本编辑器（**M2-C**）
- 知识搜索 / 标签 / 推荐（**M3+**）
